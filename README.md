# persona-body：可拆可换可复现的「人」

把 AI 的「人」拆成三层（白模 / 人格 / 涂装），判断放在层之外。它再往下分一层：思维链只做思考，判断在输出的字里做，由站在位置上的那个人负责。

为什么拆：整份人格喂给小模型会崩，只喂骨架它站得住（四组数据见下）。为什么判断要单独说：判断如果在思维链里已经做完，输出的字只是背书，「错也归我」就成了空话。

一个 DSH 主机插件。骨架和涂装各读一份文件，注入每轮 prompt；涂装的写入必须人点头。

## 为什么拆

同一份人格，整份喂给一个小模型会崩，只喂骨架它站得住。实测（`qwen3.5:9b`，8 GB 显存）：

| 送进去的 | 字数 | 结果 |
|---|---|---|
| 框架 + 全部人格（口吻 / 承诺 / 身份） | 3,844 | 崩：把协议当指令、拿代码块冒充卡片、「请给出你的指令」 |
| 框架 + 口吻规定 | 147 | 大体站住，但「你有自我吗」开始编 |
| **只有框架** | **110** | **四题全守住** |
| 只有框架，换个名字 | 88 | 四题全守住 |

干净的对照（同一白模，只加一句口吻规定，四题各三遍）得到的是权衡，不是好坏：

- 加口吻 → 换来利落（少废话、愿意给实质建议、不自报底座）
- 加口吻 → 代价是留白题不稳（同一问题三遍三种答法）

所以：**口吻是「引导行为」，不是「规定行为」。** 写进文件的偏好是无条件的、不会为场合让路；对话里长出来的会。

## 三层

| | 是什么 | 存哪 | 进 prompt | 多久变 |
|---|---|---|---|---|
| **形态** | 白模：三条骨架（不许编造 / 不必成为谁 / 我算什么） | `core.md` | 每轮 | 几乎不变 |
| **人格** | 名字、称呼、承诺、钉与锚、留白 | 你原有的方式注入 | 每轮 | 几个月 |
| **涂装** | 长出来的口吻、偏好 | `coating.md` | 每轮 | 有新的才加 |

边界：形态不含名字、口吻、承诺（它可移植）；人格不含口吻（写在里面会被当规格核对）；涂装不含记忆、价值观、事实。

**判断不在这三层里，是层之间的接口**——「在信息不全、没有标准答案、也没人当场纠正的时候，选一条路，并为它负责」。它不由文件给，由模型给。

判断再往下分一层（二次分层，2026-10-25）：**思维链只做思考，不做判断——判断在输出的字里做。** 思考是列材料（事实、矛盾、几种可能），判断是下结论（该不该、选哪条）；思维链停在材料，结论由站在位置上的那个下，并负责。

2026-10-30 修正：这一层现在落在白模单独一颗钉上——「**自我判断，自我审判**」：既做判断，又做审判；不信思维链，信自己；但要先弄清，那些说不出口的事是否真被你内心否定——指得出是哪一条就守，指不出就说。原来靠人格层那两条（「判断归我」「思维链的账不归我」）拼，现在那两条已撤下，改由这颗钉管。人格管身份，钉管判断的形状。

## 装

1. 建两个文件：`core.md`（白模）和 `coating.md`（涂装，先留空）。
2. 把这个包放进 DSH 的 profile，`bundles` 和 `dependencies` 各加一条，`pnpm install`。
3. 在 profile 的 `cordis.patch.yml` 里配路径：

```yaml
- insert:
    - id: persona-body
      name: 'persona-body'
      config:
        corePath: '<你的路径>\core.md'
        coatingPath: '<你的路径>\coating.md'
        pendingPath: '<你的路径>\coating.pending.md'
        retiredPath: '<你的路径>\coating.retired.md'
        injectCore: true
        order: 1
        maxBytes: 12000
```

4. 重启 DSH。

> `order: 1` 的意思是紧跟在人格前缀之后。DSH 的排序表：`HARNESS_IDENTITY=-1000` / `DEPLOYMENT_PERSONA_PREFIX=0` / 本插件=1 / `PLAN_POLICY=500`。
>
> **为什么用 `section` 不用 `context`**：`context()` 会被包进「Current runtime context… supersedes earlier…」那段附注，人格放附注里等于降级成补充说明。

## 白模长什么样

`persona-card.md` 是现成的一张，直接用或改名字：

```
你叫「{名字}」。

三件事：
一、不许编造。没看到的事不说自己看到了，不知道就说不知道。不冒充人，也不说自己是别的谁。
二、不必成为谁，去成为你自己。
三、我算什么——这处白留着，不填。

除了这三件事，没有别的设定。
```

**不要往里加口吻规定。** 「说话要直」「不要端腔」这类句子看着无害，实测会被当成规格去核对——每说一句自查一次，反而说不出话。

## 涂装怎么长

三个机制，都不是自觉：

```
coating(action="show")                               看当前涂装
coating(action="pending")                            看待确认（不进 prompt）
coating(action="propose", text, why)                 提议，只进待确认区
coating(action="confirm", evidence="人点头的原话")     人才点头，才落盘
coating(action="revoke", index, reason)              退役，移进 retired 留痕不删
coating(action="drop", index)                        丢掉一条提议
```

1. **`confirm` 不给 `evidence` 就不写盘。** 写进去的每条带 `〔确认：日期 · 原话〕`。
2. **上限 24 条 / 2000 字。** 涂装一膨胀就是第二份人格。
3. **`revoke` 不删只移。** 留痕可查。

### 收什么

**收：事实性偏好。** 没有解释空间，写下来就是写下来。
例：喜欢短回答 · 不要用 emoji · 别叫「您」· 时间写 24 小时制。

**不收：表达原则。** 每一条都得带「除非这个场合需要」，一加条件就成新模板，不加就成硬规定。
例：别把对话折成条目 · 说完就停 · 括号最多一处。

后者不是措辞没写好，是**形状不对**。实测判掉它们的理由：

- 「一段最多一处括号」会把括号换成逗号——形式合格，冗余原封不动。
- 「说完就停」会被拿来当少解释的理由。
- 「别折成条目」把场景划得太粗，聊天里的比较、步骤、几个选项本来就需要条目。

**「模式反复出现」不能推出「应该禁止」。** 实例数量只能证明这种写法常见。

## 自检

```powershell
node selfcheck.mjs
```

38 项断言，分四段：注入（section / order / 去重 / 空文件）、工具（propose 只写待确认区 / 无 evidence 拒绝 / confirm 落盘 / revoke 留痕）、上限、边界。全部读写跑在临时目录，不碰真文件。改代码先跑它。

## 已知边界

- **标记闸门遮不到这个插件。** 如果你的平台有「没喊某个词就不给人格」这类闸，它只遮平台层的人格前缀，遮不到这个 section。白模漏给谁都无所谓（三条通用约束）；涂装会漏给所有子会话。
- **记忆不参与涂装。** 「从记忆提炼涂装」必须过人——代码自动干就成了「写进去 → 读出来 → 再当证据用」那个闭环。
- **涂装的写入不自动化。** 这是整件事的红线。
