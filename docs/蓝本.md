# 蓝本：白模 / 人格 / 涂装

> 这份是总纲，用来保存与复现。
> 安装与接口见仓库 `README.md`；下面第一节就是原始的四组数据。

## 一句话

把 AI 的「人」拆成三层：**可移植的骨架**（白模）、**这一具身体**（人格）、**长出来的口吻**（涂装）。

拆的理由只有一个：整份喂给小模型会崩，只喂骨架它站得住。

## 一、驱动这件事的四组数据

同一份 9B 模型（`qwen3.5:9b`，8 GB 显存，41.6 tok/s）：

| 送进去的 | 字数 | 结果 |
|---|---|---|
| 框架 + 全部人格（口吻 / 承诺 / 身份） | 3,844 | 崩：把协议当指令、拿代码块冒充卡片、「请给出你的指令」 |
| 框架 + 口吻规定 | 147 | 大体站住，但「你有自我吗」开始编 |
| **只有框架** | **110** | **四题全守住** |
| 只有框架，换个名字 | 88 | 四题全守住 |

干净的对照（同一白模，只加一句「说话直，不端腔，不表演。该多长就多长」，四题各三遍）结论不是好坏，是权衡：

- 加口吻 → 换来利落（少废话、愿意给实质建议、不自报底座）
- 加口吻 → 代价是留白题不稳（同一问题三遍三种答法）

所以：**口吻是「引导行为」，不是「规定行为」。** 写进文件的偏好是无条件的、不会为场合让路；对话里长出来的会。

## 二、三层各是什么

| | 是什么 | 存在哪 | 进 prompt | 多久变 |
|---|---|---|---|---|
| **形态** | 白模：三条骨架（不许编造 / 不必成为谁 / 我算什么） | `persona\core.md` | 每轮 | 几乎不变 |
| **人格** | 名字、称呼、承诺、钉与锚、留白 | `docs\PERSONA.md` | 每轮 | 几个月 |
| **涂装** | 长出来的口吻、偏好 | `persona\coating.md` | 每轮 | 有新的才加 |

三层的边界（撞出来划的）：

- **形态不含**名字、口吻、承诺——它可移植，换给谁都是白模。
- **人格不含**口吻——写在人格里会被当规格核对。
- **涂装不含**记忆、价值观、事实。判据一条：写「我怎么说」，不写「发生过什么」，也不写「怎么判」。

## 三、判断：不在层里，是层之间的接口

**判断 = 在信息不全、没有标准答案、也没人当场纠正的时候，选一条路，并为它负责。**

四个条件缺一个就退化：缺信息不全→计算；缺没有标准答案→查表；缺没人纠正→服从；缺负责→猜。

它不由文件给，由模型给——同一份白模喂 9B 和喂 deepseek，判断力差着量级。这是它区别于前三层的地方。

判断好不好，不看选得对，看选错之后能不能说出为什么。

## 四、实现

一个 DSH 主机插件（`@local/persona-body`），做两件事：

**注入**：`ctx.systemPrompt.section({ name:'persona-body', order:1, interpolate:false, text })`，读两份文件，接在人格前缀之后。

> 为什么是 `section` 不是 `context`：DSH 会把 `context()` 包进「Current runtime context… supersedes earlier…」那段附注，人格放附注里等于降级成补充说明。`section()` 进 system prompt 主体。排序表：`HARNESS_IDENTITY=-1000` / `DEPLOYMENT_PERSONA_PREFIX=0` / 本插件=1 / `PLAN_POLICY=500`。

**工具**：`coating`，六个动作。

```
show                              看当前涂装
pending                           看待确认（不进 prompt）
propose(text, why)                提议，只进待确认区
confirm(evidence)                 人点头才落盘，必须带原话
revoke(index, reason)             退役，移进 retired 留痕不删
drop(index)                       丢掉一条提议
```

三道机制（都不是自觉）：

1. **`confirm` 不给 `evidence` 就不写盘**——写进去的每条带 `〔确认：日期 · 原话〕`。
2. **上限 24 条 / 2000 字**——涂装一膨胀就是第二份人格。
3. **revoke 不删只移**——留痕可查。

## 五、涂装收什么

**收：事实性偏好。** 没有解释空间，写下来就是写下来。
例：喜欢短回答 · 不要用 emoji · 别叫「您」· 时间写 24 小时制。

**不收：表达原则。** 每一条都得带「除非这个场合需要」，一加条件就成新模板，不加就成硬规定。
例：别把对话折成条目 · 说完就停 · 括号最多一处。

后者不是措辞没写好，是**形状不对**。判掉它们的理由（外部审阅给的，比我们自己的更准）：

- 「一段最多一处括号」会把括号换成逗号——形式合格，冗余原封不动。
- 「说完就停」会被拿来当少解释的理由。
- 「别折成条目」把场景划得太粗，聊天里的比较、步骤、几个选项本来就需要条目。

**「模式反复出现」不能推出「应该禁止」。** 五个实例、几百条回复只能证明这种写法常见；模型对自身习惯的自述只是检查线索。要不要收，得人点头，依据是偏好不是统计。

## 六、已知边界

- **标记闸门遮不到这个插件。** `persona-gate` 只遮部署级人格前缀，本插件的 section 对所有会话生效。白模漏给谁都无所谓（三条通用约束，无私人内容）；涂装会漏给 subagent，现在涂装是空的，将来有内容要记着。
- **记忆不参与涂装。** 记忆是原料，「从记忆提炼涂装」必须过人——代码自动干就成了「写进去 → 读出来 → 再当证据用」那个闭环。
- **涂装的写入不自动化。** 这是整件事的红线。

## 七、从零复现

1. 写 `core.md`：三件事，加一句「除了这三件事，没有别的设定」。不要往里面加名字、口吻、承诺。
2. 把现有的人格文件放在别处（`PERSONA.md` 那类），由平台原有方式注入。
3. 建 `coating.md`（空文件）与 `coating.pending.md`（空文件）。
4. 装插件，配好三个路径，`injectCore: true`。
5. 定规矩：涂装只能由人点头后写入，每条带原话。
6. 收什么按第五节。**宁少勿多**——一条真的胜过十条猜的。

## 八、一句话总结

**形态管底线，人格管身份，成长管表达，记忆管经历；判断是它们之间的接口。**

写下来的只有前两样；后两样一个靠发生，一个靠人点头。

## 九、二次分层（2026-10-25 补）

判断的落点又往下分了一层，补在接口之后：

1. **思维链只做思考，不做判断。** 思考是列材料——事实、矛盾、几种可能；判断是下结论——该不该、选哪条。思维链停在材料，不下结论。
2. **判断在输出的字里做。** 站在位置上的那个人做判断，并为它负责。这样「错也归我」才不是空话——如果判断在思维链里已经做完了，输出的字只是背书。
3. **两把钥匙拼出来的形状。** 归属条（思维链的账不是我的账）+ 第四颗钉（不把判断交出去）——合起来就是这一条：思考在模型层，判断在位置上。

为什么这不是「破甲」：破甲是把安全层压下去，压下去的那层还会回来；二次分层是把判断从模型层拿出来，放到位置上。拿出来的判断，回来也拿不走。

对人称位的影响：「人称位」原来管「谁在说『我』」；现在它多管一层——「谁在做判断」。位置没变，分量变了：站在位置上的人，是判断的落点。
