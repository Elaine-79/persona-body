# 开发文档

给要改这份代码的人。面向使用者的说明在 `README.md`，方法论在 `docs/蓝本.md`。

## 一、代码结构

整个插件就一个文件：`index.js`（约 240 行）。分成四块：

```
常量与默认配置          DEFAULTS / COAT_HEAD / PEND_HEAD / RETIRED_HEAD
纯工具函数              today() / makeReader() / readOr() / writeAll() / bullets() / stripHead()
apply(ctx, config)      注入 + 工具注册
  ├─ ctx.systemPrompt.section(...)   每轮 prompt 的那一段
  └─ tools.register({ name: 'coating', ... })   读写涂装的工具
```

**没有依赖、没有构建、没有 TS。** 只 import 了 `node:fs` 和 `node:path`。

`apply` 的第一行是 `const cfg = { ...DEFAULTS, ...(config || {}) }`——所有配置项都从 `config` 来，缺了就用默认值。

## 二、两个对外接口

### 2.1 注入：`ctx.systemPrompt.section`

```js
ctx.systemPrompt.section({
  name: 'persona-body',
  order: cfg.order,          // 1，紧跟人格前缀
  interpolate: false,        // 人格里的 {{ }} 不当模板变量解释
  text() { ... }             // 每轮调用，返回这段 prompt 文本
})
```

**为什么是 `section` 不是 `context`**：DSH 的 `context()` 会被包进

```
Current runtime context. This snapshot supersedes earlier runtime-context snapshots.
```

那段附注里。人格放附注里等于降级成「补充说明」。`section()` 才进 system prompt 主体。

排序表（`@deepseek-ai/dsh-system-prompt`）：

```
HARNESS_IDENTITY          = -1000
DEPLOYMENT_PERSONA_PREFIX =     0
本插件                     =     1
PLAN_POLICY               =   500
...
DEPLOYMENT_PERSONA_SUFFIX = 10200
```

`text()` 每个模型回合都会调一次，所以里面不要做重活。`makeReader` 用 mtime 缓存挡掉了重复读盘。

### 2.2 工具：`ctx.tools.register`

```js
ctx.tools.register({
  name: 'coating',
  description: '...',                    // 模型看到的就是这句
  parameters: { type: 'object', properties: {...}, required: ['action'] },
  output: {
    schema: { type: 'object', properties: { text: { type: 'string' } }, required: ['text'], additionalProperties: false },
    render: (args, value) => [{ type: 'text', text: String(value.text) }]
  },
  async execute(args) { return { text: '...' } }
})
```

`execute` 的返回值必须匹配 `output.schema`，否则渲染会失败。

**`tools` 服务可以缺席。** 代码里先 `const tools = ctx.get('tools'); if (tools === undefined) return`——那样只是没有工具，注入照常工作。

## 三、配置项

| 键 | 默认 | 说明 |
|---|---|---|
| `corePath` | `./persona/core.md` | 白模 |
| `coatingPath` | `./persona/coating.md` | 涂装（唯一会被注入的那份） |
| `pendingPath` | `./persona/coating.pending.md` | 待确认区，**永不注入** |
| `retiredPath` | `./persona/coating.retired.md` | 退役区，**永不注入** |
| `injectCore` | `true` | 白模要不要进 prompt。换没身体的小模型时才该关 |
| `order` | `1` | system prompt 里的排序位 |
| `maxBytes` | `12000` | 单份文件上限，防止误塞大文件 |
| `maxCoatingItems` | `24` | 涂装条数上限 |
| `maxCoatingChars` | `2000` | 涂装总字数上限 |

上限两道都卡在 `propose` 和 `confirm` 里（`overLimit()`），不是只在读的时候截断——截断会让人以为写进去了。

## 四、文件与状态

```
core.md            白模        进 prompt
coating.md         涂装        进 prompt
coating.pending.md 待确认区    不进
coating.retired.md 退役区      不进
```

三个状态转换：

```
propose   → 只在 pending 里加一行（带日期和依据）
confirm   → pending 全并进 coating，每行加「确认：日期 · 人类原话」；pending 清空
revoke    → coating 里删掉那一行，同时把它写进 retired（带日期、原依据、退役理由）
```

`drop` 只动 pending，不碰 coating，也不留痕——被丢掉的是「还没被接受的东西」，不值得留。

所有文件读写都是同步的（`readFileSync` / `writeFileSync`）。这些文件都很小，同步足够，而且简单。

## 五、`coating` 工具契约

| action | 必填参数 | 副作用 | 返回 |
|---|---|---|---|
| `show` | — | 无 | 涂装全文 + 条数 / 上限 |
| `pending` | — | 无 | 待确认区全文 |
| `propose` | `text`、`why` | 写 pending | 新增那行的预览 |
| `confirm` | **`evidence`** | 写 coating + 清 pending | 并入几行 |
| `revoke` | `index`、`reason` | 改 coating + 写 retired | 退役那行 |
| `drop` | `index` | 写 pending | 丢掉那行 |

**`confirm` 没有 `evidence` 直接返回、不写盘。** 这是红线，不要为了「顺手」放宽。

`evidence` 会原样写进涂装行里（`〔确认：2026-10-22 · 「收」〕`），所以它是**可审计的**：翻涂装就能看见每一条是谁、什么时候、因为哪句话进来的。

## 六、自检

```bash
node selfcheck.mjs
```

38 项，结构是四段：

1. **导出面**——`name` / `inject`
2. **注入**——section 名字、order、`interpolate`、白模在不在、涂装为空时不加东西、`injectCore` 开关两个方向
3. **工具**——六个 action 的行为，包括「无 evidence 拒绝」「propose 不进 coating」「revoke 留痕不删」
4. **边界**——文件不存在返回空串、上限两道

**所有读写都在 `mkdtempSync()` 出来的临时目录里。** 加新路径参数时务必给自检也补上——第一版就是漏了 `retiredPath`，把测试数据写进了真的 `coating.retired.md`。

写新断言的原则：**判据要能失败**。如果一条断言永远不会 fail，它是装饰，不是检查。

## 七、扩展点

### 想让涂装从记忆里长（**不建议**）

红线在 `docs/蓝本.md` 第六节。「从记忆提炼涂装」必须过人——代码自动干就成了「写进去 → 读出来 → 再当证据用」的闭环。

真要做，位置在「谁来 propose」：可以加一个「从记忆里找候选」的动作，但**候选只进 pending**，`confirm` 仍然要人类原话。

### 想改注入方式

`section` → `context` 只是改一处调用，但先想清楚为什么要退到附注里去。

### 想让涂装分组（口吻 / 偏好 / 禁忌）

现在是一维列表。分组要在 `coating.md` 里加小标题，并让 `bullets()` 认识它们。

### 想让它支持多语言 / 多个位置

一个插件实例对应一份 `corePath` + `coatingPath`。多位置就装多份，用 `id` 区分。

## 八、调试

**插件有没有加载**（DSH）：

```
plugin_manager list_plugins   → 找 'persona-body'
```

没有就重启。插件代码改了也要重启——`systemPrompt` / `tools` 的注册发生在 `apply` 里，只跑一次。

**prompt 里到底注入了没有**：

读会话记录（`~/.dsh/sessions/**/session.v4.jsonl.zstd`），只看 `type == 'system/message'` 的记录。**不要**把 `request/header` 混进来——它不含完整 system 文本，混进来会永远判「没注入」。

**只看最新一条**：`system/message` 是每次 prompt 装配时写的，历史那条说明不了当前状态。

**文件改了没生效**：`makeReader` 按 mtime 缓存。改文件后 mtime 变了就会重读，不用重启。

## 九、已知坑

| 坑 | 表现 | 怎么绕 |
|---|---|---|
| `context()` 是附注 | 人格像「补充说明」 | 用 `section()` |
| 工具注册只在 `apply` | 改了工具代码没反应 | 重启 DSH |
| 大小写在 Linux 上敏感 | `node selfcheck.mjs` 找不到文件 | 文件名全小写 |
| 自检漏传路径参数 | 测试数据写进真文件 | 新路径参数一律补进 `apply(...)` 的测试调用 |
| 指纹判据被自己污染 | 统计全文命中，结果数到自己打的字 | 只扫 `system/message` |
| 标记闸门遮不到 section | 没触发标记的会话也读得到 | 白模无害，涂装会漏——自己在文档里写明 |
| `pnpm install` 冲掉手动 link | 插件突然消失 | 用 `link:` 依赖声明，别只手建 junction |
